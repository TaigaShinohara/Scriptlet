# 外の理由（External Reasons）— 共通の思想・意図

2026-11-27 に大河が全プロジェクト共通の前提として定めた思想。Scriptlet の「期限・お金の暦」方向（サブスク更新日・ポイント失効・手続き期限をウィジェットに出す仕掛け）の設計は、この文書を前提にする。他プロジェクトでも同じ思想で設計する。

## 思想

1. **理由は作らない、外にあるものに乗る**
   習慣の理由をアプリの中で必死に作る（通知で煽る、ストリークで縛る）のではなく、暦・天気・他人の予定・身体のリズム・お金の暦など、世の中で既に回っている理由にアプリが「乗る」。アプリは理由の製造者ではなく、理由と人を繋ぐ受け皿である。

2. **盛らない・煽らない**
   外の理由は日付や天気という事実なので、アプリが嘘をつけない・水増しできない。そこがユーザーの信頼に直結する。演出で盛らず、事実を静かに届ける。

3. **途切れても責めない**
   ストリークや連続記録で縛らない。途切れは失敗ではなく、「戻ってきた」が一番のイベント。復帰を祝う。罪悪感で続けさせる設計は禁止（特にメンタルに関わるもの）。

4. **成功の定義**
   毎日開かせることではなく、「必要な日に、ちょうど届くこと」。開かれない日があってよい。習慣化して卒業されることも敵とせず、その先の「区切りに戻ってくる場所」まで含めて設計する。

5. **宗教そのものは扱わない**
   借りるのは「外が理由を供給する」という構造だけ。

6. **マネタイズは理由の供給とセットで考える**
   シーズンパス、失効・期限の静かなお知らせなど。煽って売らない。

## Scriptlet（期限系プリセット）への落とし込み

- 表示文言は事実だけ：「あと◯日」「◯月◯日に更新」。煽り文句・感嘆符・赤色は使わない。色づけは 無彩色 → 淡オレンジ（30日以内）→ ピンク（7日以内）まで。
- 期限を過ぎた項目は「遅れた」と責めない。繰り返し（repeat）のあるものは次の周期へ静かに切り替え、「過ぎました。次は◯月◯日」とだけ出す。
- 毎日開かせるための日替わり演出は入れない。見た目が変わるのは、日付が実際に近づいたときだけ。
- データ（期限レジストリ）はアプリの外に置くのが本筋：外部JSONを読みに行く形が思想そのもの。他アプリ・他プロジェクトとも同じフォーマットを共有できる。
